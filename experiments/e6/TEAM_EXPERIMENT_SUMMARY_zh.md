# HDB 租金预测：实验路线、结果与当前结论

本文档整理目前项目中与 E1–E6、首次 Kaggle 提交及后续模型改进有关的实验，供组员共享和最终 report 写作使用。重点记录每次实验为什么做、具体改变了什么、得到什么结果，以及哪些问题已经缓解、哪些问题仍未解决。

## 1. 当前结论

目前本地正式验证表现最好的单模型是：

> **阻尼市场趋势 + 不含长期时间变量的 CatBoost 残差模型**

其正式验证结果为 RMSE **465.560**、MAE **341.384**、R² **0.5005**。模型把租金拆为“可外推的市场时间水平”和“房源属性造成的价格差异”：市场时间水平使用受限的阻尼趋势外推；CatBoost 预测残差时删除 `month_index` 和 `year`，只保留 `calendar_month` 表示季节性，并使用房屋、完整地址及 HDB/MRT/Malls 辅助特征。

三个未来窗口的核心比较如下：

| 模型 | 2022-06 起点 | 2022-12 起点 | 正式 2024-04 起点 |
|---|---:|---:|---:|
| B CatBoost | 783.058 | 605.373 | 472.236 |
| 阻尼趋势 + LightGBM | **726.913** | 605.688 | 472.340 |
| B CatBoost 与趋势 LightGBM 等权平均 | 752.921 | **587.441** | 469.887 |
| **阻尼趋势 + 无长期时间变量 CatBoost 残差** | 729.910 | 596.171 | **465.560** |

新模型在正式期明显最好，在 2022-06 窗口接近趋势 LightGBM，在 2022-12 窗口优于两个单模型但不如简单平均。因此它是当前最强、方法结构也最清晰的候选，但不能声称在所有市场时期都必然最好。

## 2. 任务性质与评价协议

数据包含不同月份发生的 HDB 租赁记录。老师澄清，这不是同一套房按固定频率重复观测的纯时间序列。相同楼栋、房型、面积和模型的记录也可能来自不同房屋单元，因为数据没有唯一房屋或合同 ID。因此，更合适的表述是带时间维度的横截面数据，或无法确认个体身份的 panel-like / repeated cross-sectional data。

时间仍然重要，因为测试集整体位于训练集之后。正确的建模目标是：

> 对未来月份出现的一批房源进行横截面租金预测，同时处理整体市场价格随时间变化的问题。

不能把同楼同属性记录直接解释为同一套房的历史轨迹；可以把它们作为同类房源或地址群组，估计群组历史价格水平。

### 2.1 固定划分与历史回测

| 起点 | 训练期 | 评价期 | 训练 / 评价行数 |
|---|---|---|---:|
| 2022-06 | 2021-01–2022-06 | 2022-07–2023-10，16 个月 | 55,008 / 44,893 |
| 2022-12 | 2021-01–2022-12 | 2023-01–2024-04，16 个月 | 70,182 / 47,595 |
| 正式 2024-04 | 2021-01–2024-04 | 2024-05–2025-03，11 个月 | 117,777 / 31,582 |

每个起点只训练一次，然后一次性预测完整未来区间，期间不加入评价期真实租金。两个历史评价区间存在重叠，而且都是看到正式结果后增加的回顾性稳健性检查，因此不能当作三个完全独立的测试集，也不能简单平均三个 RMSE 选冠军。

主要指标为 RMSE；同时记录 MAE、R² 和 Mean Error。Mean Error 定义为预测减真实，负值表示整体低估。由于 RMSE 对少数大误差施加平方惩罚，报告中必须同时检查误差分布和分组表现。

## 3. 数据清理与基础特征

统一清理包括：规范化 `TOWN`、`BLOCK`、`STREET`、`FLAT_MODEL` 的大小写与空格；将 `3-room` 和 `3 room` 等房型写法统一；删除训练集中恒定的 `FURNISHED` 和 `FEE`；对训练集删除所有字段和目标都相同的精确重复行。150,000 条原始训练记录清理后剩余 149,359 条。测试集不去重，以保持 Kaggle 行数和 ID 顺序。

从原字段派生：

- `flat_age = approval_year - LEASE_COMMENCE_DATE`；
- `month_index = (year - 2021) × 12 + month - 1`；
- `year`、`calendar_month` 等替代时间表示；
- 完整地址楼栋标识 `TOWN + STREET + BLOCK`，只代表地址群组，不代表唯一房屋。

基础 Core 特征为：`FLOOR_AREA_SQM`、`flat_age`、时间、`TOWN`、`FLAT_TYPE`、`FLAT_MODEL`、`BLOCK`、`STREET`。F0 只包含面积、房龄、时间、TOWN 和房型。

提供的辅助数据经过训练无关的静态连接，形成：

- HDB：经纬度、最高楼层、SUBZONE、PLANNING_AREA；
- MRT：最近站距离、站名、线路数；
- Schools：最近小学/中学距离、1/2 km 内学校数量；
- Malls：最近商场距离和名称；
- COE 和 Stock：滞后一个日历月的宏观指标。

HDB、MRT、Schools 和 Malls 使用静态地理近似，没有重建历史设施状态。当前假设不允许使用老师提供文件之外的外部数据。

## 4. E1：模型基线比较

最初模型比较的保存结果如下：

| 模型 | RMSE | MAE |
|---|---:|---:|
| TabM（保存日志） | 474.00 | 344.00 |
| CatBoost | 482.68 | 358.50 |
| LightGBM | 483.09 | 359.34 |
| HistGradientBoosting | 484.21 | 360.63 |
| Extra Trees | 492.94 | 368.43 |
| Random Forest | 493.00 | 368.47 |
| Linear / Ridge | 约 616.28 | 约 460.27 |
| Dummy | 839.61 | 683.05 |

LightGBM 被选作 E2–E6 的受控工作模型，原因是性能有竞争力、训练快、能处理非线性和缺失值，并且方便固定参数比较特征。这个选择不证明 LightGBM 在所有输入和调参条件下最优；早期 TabM、CatBoost 与 LightGBM 的特征和训练条件并非完全相同。

后续固定 LightGBM 参数为：`n_estimators=500`、`learning_rate=0.05`、`num_leaves=31`、`random_state=42`、`n_jobs=-1`、`verbosity=-1`，没有 early stopping 或大规模参数搜索。

## 5. E2：主表特征与高基数编码

### 5.1 特征增量设计

E2.1–E2.4 均以 F0 为共同对照，并非逐项累加；E2.5 为完整 Core。

| 配置 | 相对 F0 新增内容 | 正式 RMSE |
|---|---|---:|
| E2.0 | 无 | 485.157 |
| E2.1 | FLAT_MODEL | 484.367 |
| E2.2 | STREET | 481.023 |
| E2.3 | 复合楼栋 ID | 482.756 |
| E2.4 | LATITUDE、LONGITUDE | **479.446** |
| E2.5 | 完整 Core | 479.497 |

动机是判断房屋模型、细粒度地址和连续地理位置是否提供超出 Town/房型/面积的信息。结果表明 STREET 和坐标有明显增量；坐标能在连续空间共享相邻区域信息，避免完全依赖稀疏地址标签。

### 5.2 编码比较

低基数类别使用训练内拟合的 One-hot；高基数 BLOCK、STREET 比较：

| 编码 | 正式 RMSE |
|---|---:|
| 数值 Ordinal，未知为 −1 | **479.497** |
| Frequency | 479.806 |
| LightGBM Native categorical | 482.635 |

因此早期实验固定 Ordinal。其局限是把无序类别映射为普通数值，树的阈值会引入人工大小关系。这个结果只适用于当时的 Core、LightGBM 和固定参数，不能推广为所有模型或完整 E6 特征上的最佳编码。

| 配置 | 新增特征组 | 正式 RMSE |
|---|---|---:|
| E3.0 | Core | 479.497 |
| E3.1 | + HDB | 477.780 |
| E3.2 | + MRT | 476.603 |
| E3.3 | + Schools | 476.480 |

| D2 | E3.3 + COE | 476.111 |

HDB 和 MRT 的加入有明确动机：补充连续空间、建筑尺度和交通可达性。Schools 的正式增益只有 0.122，Malls 小幅改善约 0.736。COE、Stock 和全量组合没有稳定增益，表明单个有效特征组不能直接相加，宏观变量也可能与时间特征竞争切分或超出树的数值外推能力。

E4 在固定基础特征和 LightGBM 下，只改变时间表示：

| 配置 | 时间表示 | RMSE |
|---|---|---:|
| E4.0 | month_index | 485.358 |
| E4.1 | year + calendar_month | **484.518** |
| E4.2 | month_index + calendar_month | 484.691 |
| E4.3 | year + quarter | 484.971 |
| E4.4 | month_index + year + calendar_month | 484.691 |

E4.1 相对 E4.0 只改善 0.840 SGD，即 0.173%，并且在正式期最后三个月全部变差。结果说明日历月份可能带来小幅季节信息，但没有证据证明它解决长期外推。

## 8. E5：时间稳健性与误差分析

E5 将九个固定 LightGBM 特征配置放入两个历史起点和正式窗口。最重要的结果是：Core 和 HDB 在三个窗口中都有方向一致的收益，而 MRT、Schools、Malls 和宏观变量具有时期依赖性。

| 配置 | 2022-06 | 2022-12 | 正式期 |
|---|---:|---:|---:|
| F0 | 795.464 | 618.427 | 485.157 |
| Core | 793.140 | 615.882 | 479.497 |
| Core + HDB | **789.340** | **610.977** | 477.780 |
| + MRT | 789.808 | 611.454 | 476.603 |
| + Schools | 790.180 | 612.041 | 476.480 |
| + Malls | 789.995 | 611.723 | **475.745** |

时间误差在不同市场窗口差异很大。E3.3 在 2022-06 起点的 Mean Error 随预测跨度由约 −194 加深至约 −621；如果事后完美删除每月平均偏差，RMSE 可由 790.18 降至 614.82，月度平均偏差约占 MSE 的 39.46%。2022-12 窗口该比例为 5.81%，正式期只有 1.20%。这些“完美校正”使用评价标签，只是误差分解，不是可实现成绩。

正式期误差集中于租金两端：真实租金 ≤2000 的记录只占约 5.88%，却贡献约 32.6% 平方误差，模型平均高估约 1006；真实租金 >3600 的记录贡献约 26%，平均低估约 446。最大约 1% 的绝对误差样本贡献约 16.2% 的平方误差。Jurong West、大户型和 Executive 的误差也较高。未见复合地址只占约 0.415%，不是总体误差的主要来源。

E5 的关键动机转变是：继续加入静态位置特征无法解决历史窗口中的整体低估，因此需要显式测试可外推市场趋势。

E6 将此前证据整合为四个受控配置：

| 配置 | 特征 | 时间表示 |
|---|---|---|
| A | Core + HDB + MRT + Schools + Malls | month_index |
| B | Core + HDB + MRT + Malls | month_index |
| C | B 的非时间特征 | year + calendar_month |
| D | Core + HDB + Malls | month_index |

B 对 A 删除 Schools；C 对 B 只替换时间表示；D 对 B 删除 MRT。

| 配置 | 2022-06 | 2022-12 | 正式期 |
|---|---:|---:|---:|
| A | 789.995 | 611.723 | 475.745 |
| B | **789.307** | **611.599** | 476.639 |
| C | 886.021 | 845.120 | **474.718** |
| D | 790.181 | 613.157 | 476.805 |

C 在正式期最低，但相对 B 在两个历史窗口分别恶化约 96.7 和 233.5 SGD。`year + calendar_month` 对树模型的长期时间水平表达不足，局部正式优势不能迁移到其他市场阶段。E6 因而推荐 B 作为精简稳健方案；这是跨时期表现和简洁性的取舍，不是 B 在每个窗口都最好。删除 MRT 在三个窗口都使 RMSE 和 MAE 变差，因此保留 MRT。

## 10. 首次 Kaggle 提交与差距诊断

第一次提交使用全量重训的 E6-C，Kaggle RMSE 为 **449.75063**，用户报告排名 34，第一名为 **172.42640**。从 449.75 降至 172.43 需要 RMSE 下降约 61.7%，对应 MSE 减少约 85.3%，远大于 E2–E6 中亚百分比级的特征增量。

提交文件已核对 50,000 行、ID 顺序、有限预测、训练内编码和辅助数据连接，没有证据表明格式错位或大规模连接失败造成主要差距。本地 C 正式 RMSE 474.72 与 Kaggle 449.75 处于相近量级，但评价样本和训练截止不同，不能把差值解释为精确提升。

对 C 重新拟合后，全部训练样本拟合内 RMSE 约 463.01，最近 11 个训练月约 537.81，说明误差在未来预测前已经存在。高训练误差可能来自模型容量不足、缺少房屋/合同信息或标签条件离散度，单凭该结果不能断言欠拟合。

正式验证期的诊断显示：

- 完美修正所有月度平均偏差，RMSE 仍约 472.17；
- 假设所有真实租金 ≤2000 的记录都预测正确，其余不变，整体 RMSE 仍约 389.07；
- 假设低租金和 >3600 高租金都预测正确，其余不变，整体 RMSE 仍约 306.96。

因此时间偏差和低租金问题都重要，但任何单一问题都不能解释全部差距。

约 25.4% 的正式验证记录属于“清洗后可见输入重复，但租金不同”的组。例如 2024-08、Jurong West、同一楼栋和街道、5-room、110㎡、improved、租约起始 2004 的两条原始记录租金分别为 1200 和 4200；原始街道大小写不同，但其他字段一致。它们不能被确认是同一套房。缺少楼层、装修、合同条件、出租范围和唯一单元 ID，使模型无法完全区分这类记录。

## 11. 疑似异常清理实验

由于 1200 等记录可能是录入异常或房间租金，增加了训练期相近房源异常筛选。规则按季度、Town、房型和 20㎡ 面积档寻找至少 30 条同类记录；不足时逐步放宽到季度/Town/房型和季度/房型。对租金取对数，使用组内中位数与 MAD，超出 `median ± max(3.5 × 1.4826 × MAD, log(1.5))` 的训练记录标为疑似异常。只删除训练记录，完整保留验证集。

正式训练部分删除 1,515 条，其中偏低 1,496 条、偏高 19 条。C 的正式 RMSE 由 474.718 改善到 **472.678**，MAE 由 352.379 改善到 **342.556**，三个窗口均小幅改善。但正式期低租金组 RMSE由 1122.03 恶化至 1174.57，中高租金组改善。模型整体预测水平提高，Mean Error 由 −42.75 变为 +7.00。

这个实验支持“稳健筛选可能小幅改善整体 RMSE”，不证明被删记录一定错误。若测试集也含低价记录，删除训练低价样本会使它们更难预测。因此最终趋势 CatBoost 没有自动采用该删除规则。

## 12. 地址、编码与历史租金统计

### 12.1 完整地址

将单独 `BLOCK` 替换为 `TOWN + STREET + BLOCK`，正式 RMSE 由 474.718 小幅改善到 474.383。单独楼号不是全局唯一，完整地址在业务含义上更合理，但类别更稀疏，因此收益有限。

### 12.2 完整 E6 特征上的编码

| 编码/模型 | 2022-06 | 2022-12 | 正式期 |
|---|---:|---:|---:|
| 完整地址 Ordinal | 885.990 | 845.147 | 474.383 |
| Frequency | 886.955 | 844.462 | 474.736 |
| 稀有类别合并 One-hot | 860.788 | 846.657 | 474.702 |
| LightGBM Native categorical | 876.563 | 844.880 | 478.694 |
| 时间安全平滑目标编码 | **815.385** | **636.744** | **474.158** |

目标编码使用 prior weight 20。每个训练月份只读取此前月份的类别租金统计；验证期只读取预测起点前的训练标签。它明显缓解历史窗口中的时间问题，但在正式期只改善约 0.22 SGD，说明地址历史价格和整体市场趋势仍有混合。

### 12.3 六个月历史统计

另一组实验为 Town×房型、Street×房型、Building×房型构造此前六个月的平滑均值和样本量，稀疏组逐级向更粗层级收缩，prior weight 同为 20。历史统计将 C 的两个历史窗口由 886.02/845.12 改善到 802.73/612.02，但正式期退步到 477.08。它主要补偿 C 对历史整体水平的表达缺陷，没有形成跨窗口统一胜者。

## 13. CatBoost、趋势模型与集成

CatBoost 固定参数为 `iterations=1000`、`depth=6`、`learning_rate=0.05`、`loss_function=RMSE`、`random_seed=42`、`has_time=True`。类别列直接交给 CatBoost；训练行按月份排序，以使用有序类别统计。

### 13.1 直接 CatBoost

- C CatBoost：完整地址 + E6-C 的 `year + calendar_month`。正式 RMSE **469.532**，但历史窗口为 817.702/687.228。
- B CatBoost：完整地址 + `month_index`。正式 RMSE 472.236，历史窗口 **783.058/605.373**，相对 B LightGBM 三个窗口都稳定改善约 0.8%–1.0%。

C CatBoost 在正式窗口最好，B CatBoost 跨时期更稳定。这说明 CatBoost 的类别交互处理有效，但时间表示仍决定历史外推表现。

### 13.2 趋势估计

趋势部分先用带正则的 Hedonic Ridge 同时拟合房源属性和每月虚拟变量，Ridge `alpha=20`。模型从控制房源构成后的月度系数中，取最近 12 个月拟合斜率，并以最后 3 个月平均水平作为锚点。

比较三种未来趋势：

- Flat：保持截止月水平；
- Linear：近期斜率无限线性延伸；
- Damped：有效预测距离为 `6 × (1 − exp(−h/6))`，短期延续、长期逐渐趋稳。

| 趋势 + LightGBM | 2022-06 | 2022-12 | 正式期 |
|---|---:|---:|---:|
| Flat | 805.840 | 614.512 | 473.411 |
| Linear | **657.864** | 746.274 | **471.752** |
| Damped | 726.913 | **605.688** | 472.340 |

线性趋势在继续上涨的窗口提升很大，但在 2022-12 起点发生过冲；该起点估计近期斜率约每月 61.6 SGD，持续 16 个月并不合理。阻尼趋势在三个窗口均优于原始 C，也略优于 B LightGBM，是更安全的长期外推方式。纯 Hedonic Ridge + 阻尼趋势正式 RMSE 480.815，说明房源属性仍需要非线性树模型。

### 13.3 简单等权集成

`0.5 × B CatBoost + 0.5 × 阻尼趋势 LightGBM` 的 RMSE 为 752.921/587.441/469.887。它利用两类模型不同的误差，在 2022-12 和正式窗口改善，但 2022-06 被较弱的 B CatBoost 拉低。权重 0.5 是可解释的固定值，没有根据验证集搜索最优权重。

## 14. 当前最新模型：阻尼趋势 + CatBoost 残差

### 14.1 动机

B CatBoost 擅长高基数类别和类别交互，但树模型不能自然将长期时间趋势外推到训练范围之外。趋势 LightGBM 能显式外推市场水平，但 LightGBM 对地址类别关系的表达不如 CatBoost。因此，将趋势和 CatBoost 在模型内部按职责分工：趋势负责长期市场变化，CatBoost 只负责房源残差。

### 14.2 精确设计

首先估计训练月份的调整后市场效应，并用上述阻尼趋势预测未来市场水平。然后定义：

`residual = MONTHLY_RENT − fitted_market_effect`

CatBoost 的残差输入明确删除 `month_index` 和 `year`，避免树模型再次学习无法外推的长期时间；保留 `calendar_month` 作为 1–12 月季节性类别。其他输入为：

- 房源：面积、房龄、Town、房型、房屋模型；
- 地址：Street、`TOWN + STREET + BLOCK` 完整地址；
- HDB：经纬度、MAX_FLOOR、SUBZONE、PLANNING_AREA；
- MRT：最近站距离、站名、线路数；
- Malls：最近商场距离和名称。

最终预测为：

`future damped market effect + CatBoost predicted residual`

### 14.3 结果和错误分析

| 模型 | 2022-06 | 2022-12 | 正式期 |
|---|---:|---:|---:|
| B CatBoost | 783.058 | 605.373 | 472.236 |
| 阻尼趋势 LightGBM | **726.913** | 605.688 | 472.340 |
| 两者等权平均 | 752.921 | **587.441** | 469.887 |
| **阻尼趋势 CatBoost 残差** | 729.910 | 596.171 | **465.560** |

正式期新模型在 11/11 个月优于 B CatBoost 和趋势 LightGBM，在 10/11 个月优于简单平均。2022-06 它在 16 个月中均略差于趋势 LightGBM，总体只差约 3 SGD；2022-12 它优于两个单模型，但简单平均更好。

正式期按真实租金分组：

| 租金范围 | B CatBoost | 趋势 LightGBM | 简单平均 | 最新模型 |
|---|---:|---:|---:|---:|
| ≤2000 | 1128.15 | 1135.34 | 1130.95 | **1119.58** |
| 2000–3600 | 349.44 | 348.47 | 346.07 | **342.55** |
| >3600 | 546.39 | 544.70 | 542.41 | **538.86** |

最新模型在三个价位都改善，但低租金 RMSE 仍超过 1100。它解决了部分模型表示和时间外推问题，没有解决数据缺少出租范围、单元楼层、装修和合同条件等信息的问题。

## 16. 已解决和未解决的问题

### 已经得到较明确答案

- HDB 静态地理属性在三个时间窗口都有稳定增量；MRT、Schools、Malls 的边际价值更依赖时期。
- `year + calendar_month` 在单一正式窗口的小优势不能保证长期迁移；树模型需要显式的外推机制。
- 数值 Ordinal 在早期 LightGBM Core 上胜过 Frequency 和 Native，但理论局限真实存在；换模型后 CatBoost 的类别处理更有效。
- 完整地址业务含义更合理，但单独替换只能带来很小提升。
- 历史目标统计需要严格按时间防泄漏；它能缓解历史低估，但不能替代市场趋势建模。
- 线性趋势可能严重过冲；阻尼趋势在三个窗口更稳健。
- CatBoost 与趋势在模型内部按职责拆分，比简单改变编码、删除异常或简单集成更适合当前正式窗口。

### 仍未解决

- 低租金和高租金两端仍贡献大量平方误差，尤其低租金记录可能混有不同出租口径，但没有字段可验证。
- 缺少唯一房屋 ID、楼层、装修、合同类型和出租范围，清洗后输入相同的记录可能对应不同租金。
- 历史窗口重叠，正式验证集也被多次用于比较，结果存在选择偏差；Kaggle 隐藏测试仍是更独立的检验。
- 当前只使用单个随机种子，没有统计显著性检验；小于 1 SGD 的差异不应被过度解释。
- 辅助地理表是静态快照，不能反映设施在历史月份的真实开放状态。
- 当前最佳本地 RMSE 465.56 与榜首 172.43 的差距仍极大，不能保证新提交会产生同比例的 Kaggle 改善。

## 17. 建议的 report 主线

最终报告可按以下逻辑组织：EDA 发现明显市场时间变化和位置差异；E1 建立模型基线；E2 证明细粒度地址和连续空间信息有效；E3 通过逐组消融选择地理辅助特征；E4 说明简单替换日期表示收益有限；E5 用多个预测起点揭示时期依赖和历史整体低估；E6 形成精简整合配置，并证明单窗口最优时间表示缺乏迁移性；首次 Kaggle 和误差诊断进一步显示静态特征拼接不足；最终提出“可外推市场趋势 + CatBoost 横截面残差”的两部分模型。

报告应明确：这不是纯时间序列；完整地址是同类房源群组，不是唯一房屋；历史统计和类别编码均按训练时间拟合；月度 oracle 校正和“把某租金组预测正确”的数字只用于诊断；疑似异常删除不能证明标签错误；模型选择基于多窗口描述性证据，而非三个独立测试集或统计显著性。
